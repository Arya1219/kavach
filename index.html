The problem

Digital-arrest, UPI and KYC scams reach people in Hindi, Tamil, Bengali, Marathi and code-mixed Hinglish. Most detectors are English-first, and a good one needs access to private messages that nobody wants to upload to a server.

आपके नाम से एक पार्सल पकड़ा गया है। आप डिजिटल अरेस्ट में हैं, अभी ₹50000 भेजें।
Sir aapka SBI account block ho jayega, link click karke OTP bhejo.

How it works

Sarvam LLM writes Indic scam data→ Each phone trains on its own language→ Updates clipped + noised (DP)→ Server averages, never sees messages→ Sarvam explains + speaks the warning

Federated learning

20 simulated phones, each holding messages in a single language (non-IID). Only model updates are shared.

Differential privacy

Per-phone update clipping plus Gaussian noise (DP-FedAvg), with ε tracked by RDP accounting.

Char n-gram model

Hashed character n-grams handle spelling variation and transliterated Hinglish with a tiny on-device model.

Sarvam AI

LLM for data generation and plain-language explanations, text-to-speech for spoken alerts in the user's language.

Adversarial loop

An LLM scammer rewrites scams to dodge the detector; evasions are fed back to retrain the federation.

Run it

pip install -r requirements.txt
export SARVAM_API_KEY=your_key
python gen_data.py   # Sarvam writes the dataset
python fed.py        # federated + DP training
python app.py        # demo UI

Honest limits

The federation is simulated on one machine and the dataset is LLM-generated, not real SMS. With only 20 simulated phones the privacy budgets are large, so this demonstrates the mechanism rather than a strong guarantee. Next steps: real on-device training, larger federations, and human-verified Indic scam data.
